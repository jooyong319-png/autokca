# question-inbox — 질문 후보 대기함

> **생성은 자동, 발행은 수동**(브리프 §3). 주간 자동화가 여기에 후보를 쌓고,
> **사람이 고른 것만** `lib/questions.ts`로 올라간다.
> 큐 이력과 작성 규칙은 [[questions-log]], 이 위키 사용법은 [[SCHEMA]].

## 🔴 왜 자동 발행을 안 하나

`id`와 `slug`은 **배포 후 영구 불변**이다.

| 필드 | 무엇인가 | 잘못 나가면 |
|---|---|---|
| `id` | 집계 테이블 키(`tallies.question_id`) | 바꾸는 순간 **그 질문의 표가 전부 사라진다** |
| `slug` | URL(`/q/축의금-5만원`) | 색인과 외부 링크가 깨진다 |

그래서 오타 하나가 영구적이다. 게다가 **재미가 상품**이라 안 웃긴 게 섞이면 바로 티가 나고,
규칙 4(성별·정치·종교)를 어긴 질문 하나가 초반 첫인상을 통째로 망가뜨린다.
→ 사람이 한 번 보는 값이 비용보다 훨씬 크다.

## 올리는 법

1. 아래 후보 중 마음에 드는 것의 `- [ ]`를 `- [x]`로 바꾼다
2. `lib/questions.ts`의 배열에 추가한다 — **id·slug 중복을 반드시 다시 확인**
3. `npm run build`로 통과 확인 후 배포
4. 올린 항목은 이 파일에서 **지우고** [[questions-log]] 이력에 한 줄 남긴다

기각한 것도 지운다. 다만 **왜 기각했는지**는 [[questions-log]]의 "기각한 소재"에 적는다 —
안 그러면 자동화가 같은 걸 또 가져온다.

## 후보 형식

```
- [ ] **질문 문장?**
      - 갈래: 진지 | 병맛 · 주제: money|work|manners|life|office|commute|food|messenger
      - 선택지: `A` / `B`
      - 제안 id: `kebab-ascii` · 제안 slug: `한글-슬러그`
      - 왜 갈릴 것 같은가: (한 줄)
```

## 검수할 때 보는 것 (작성 규칙, [[questions-log]]와 동일)

1. **답이 둘로 갈리는가** — 90:10이 뻔하면 재미가 없다
2. **어느 쪽을 골라도 부끄럽지 않은가** — 한쪽을 고르면 이상한 사람이 되는 질문은 버린다
3. **선택지가 짧은가** — 투표 칸 한 줄에 들어가야 한다(최장 11자 실측)
4. 🔴 **성별 갈등·정치 진영·종교가 아닌가** — 논쟁은 되지만 모더레이션 부담이 폭발한다.
   사람 손이 거의 안 들어가는 모더레이션을 전제로 설계했다
5. **기존 103개와 겹치지 않는가** — 표현만 다른 같은 질문이 흔하다
6. **진지는 검색되는 말인가** — 진지의 존재 이유는 유입이다.
   "축의금 5만원 적나요"는 검색하지만 "화장실 갈 때 휴대폰"은 아무도 안 친다(그건 병맛 담당)
